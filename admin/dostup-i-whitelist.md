# Доступ и SpringAuth

Проходка, привязка Discord и подтверждение подключения — отдельные этапы. Проходка разрешает игру, `/claim` связывает аккаунт с Discord, а подтверждение разрешает конкретный вход.

## Выдать или продлить проходку

Выполняется доверенным администратором с `springauth.admin` в контексте SpringAuth/Velocity:

```text
/springauth grant <ник> <срок>
```

Сроки: `12h`, `30d`, `4w`, `permanent`. Для новой привязки команда выдаёт одноразовый код; передай его игроку приватно. Повторная выдача заменяет предыдущий неиспользованный код.

Ник указывай **точно, с учётом регистра**. Не меняй его написание произвольно: игровой профиль зависит от точного имени.

```text
/springauth status <ник>
/springauth revoke <ник>
/springauth sync <ник>
```

`status` показывает доступ, `revoke` отзывает его и отключает игрока, `sync` проверяет состояние. Не выдавай доступ только по наличию Discord-роли — роль отображает статус, а сервер проверяет саму проходку.

## Провести игрока через первый вход

1. Выдай проходку и код.
2. Игрок выполняет `/claim CODE` в Discord.
3. Игрок запускает Minecraft Java 26.3 с привязанным ником и входит на `play.springrp.ru`.
4. При входе по нику бот присылает подтверждение; до ответа игрок остаётся в комнате ожидания.
5. После подтверждения текущее соединение автоматически переводится на основной сервер.

Проверенный Microsoft-вход через SpringRP Launcher может заменить повторную кнопку подтверждения, но не проходку и не первоначальный `/claim`.

## Доверенные подключения

Подтверждение входа по нику создаёт 30-минутную сессию для того же аккаунта, Discord и IP. Повторное подключение не продлевает её. Смена адреса требует подтверждения. Отклонение входа и отзыв проходки удаляют доверенные сессии.

Если бот не пишет, проверь привязку и настройки личных сообщений Discord. Не проси у игрока пароль Microsoft и не публикуй его код `/claim`. Инструкция, которую можно отправить игроку: [доступ и вход](../osnovnaya-informaciya/dostup-i-launcher.md).
